# Marking guides and mocks

## Write the marking guide before the question's solution
A guide says where each mark is and what earns it. Types of mark:
- **Method marks**: for the right approach, even if the arithmetic slips.
- **Accuracy marks**: for the right figure.
- **Follow-through marks**: for using the learner's own earlier figure correctly. If an early error carries into later lines, penalise it once.
- **Theory marks**: one mark per correct, relevant point. Half a mark for a point with no explanation. Cap at the stated number of points.
- **Presentation marks**: for the requested format (a table, a memo, a report, headings). State them separately so the learner sees how many marks are format.

Template:
```
Question 3 (20 marks)
(a) Calculate X                                   8 marks
    - correct layout / proforma                   1
    - step 1 working (figure: 1,200)              2
    - step 2 working (figure: 3,400)              2
    - final answer                                1
    - follow-through if step 1 is wrong           2 (method only)
(b) Discuss Y (any 4 points, 1 mark each, 1 for example)   5 marks
(c) Present in the format asked (memo)            2 marks
```
Check the marks add up to the total.

## Mock checklist
1. Same time limit, number of questions, choice rules and mark split as the real paper (from `study/map.md`).
2. Topics in the proportions the map shows. At least one question from the learner's weakest high-weight topic.
3. Each question is original or clearly a variant ("original practice, not a past paper").
4. Marking guide written first. Solutions verified with `verify_numbers.py`.
5. A score sheet: marks per question, total, and a line for each lost mark with a cause (concept, method, arithmetic, reading, time, presentation).
6. Instructions to the learner: real clock, no notes, phone away, read the paper for the stated reading time, choose questions in the first five minutes.

## Marking an attempt
Table to give back:

| Question | Marks available | Earned | Where marks were lost | Fix |
| --- | --- | --- | --- | --- |

Then: total, three biggest lost-mark causes, and the one habit change that would add the most marks (for example "write the layout first", "show the working line", "state the method asked for").

Rules for fair marking:
- Mark what is written, not what the learner probably meant. If a line is unreadable, say so and ask.
- Do not give marks for correct theory that does not answer the question asked.
- Accept a different method if it is valid and complete. Say so.
- If the official answer seems wrong, show both and mark against the version the real marker would reward.
